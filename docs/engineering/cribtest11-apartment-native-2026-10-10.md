## Actual source integration

`BaddieCompanionNativeApartment.h/.cpp` adds a transient, nonreplicated actor component as a default subobject of the existing local SlicePlayerController. The component has no independent ticker, HTTP/session owner, credential, camera, pawn, movement controller or route solver. The module adds only the native NavigationSystem dependency.

The controller now offers validity-checked preparation/status, room-camera and doorway-approach copies. Each refresh/preparation/copy goes through the existing CopySnapshot boundary. The status records missing content, incomplete inventory, unavailable admission/presentation and unverified daylight/render acceptance. Failure copies clear their output. Native content is removed before exact input replacement, even when IDs and revision are unchanged. Access loss, re-pair, offline entry and teardown clear it with the existing private presentation owner.

Trusted content setup requires an exact saved snapshot match, explicit native level references, one binding per existing adjacency endpoint, real doorway/approach actor names and rigid yaw/translation-only whole-room transforms. No package path is committed or derived from a GLB key. Duplicate/missing endpoints, mismatched connections, nonrigid transforms, unsupported doors and failed loads/anchors reject replacement and retain no old native selection. A supplied home-living remains the living endpoint irrespective of display name. Missing home-living in the narrow grant does not create another account room.

The native load implementation uses UE's runtime level instances, initially invisible, without reuse of old private instances. GC references retain pending streams while owned. There are no async callbacks holding documents or old request identities. Clearing immediately hides actors/components, stops collision/ticks and deactivates them, then requests native unload/removal and drops retained plans/bindings. Native unload is deferred and its actual lifetime behavior is unverified. No load branch is reachable from current read-only access: it is fenced by incomplete authorised inventory, unavailable saved-render readiness and the absent standalone admission implementation. No caller-provided admission boolean bypasses those boundaries. IsWalkThroughReady stays false; no source flags assert physical completion.

Canonical doorway copying implements only bedroom-v02 and Pat studio/bedroom-v01 from the exact reference. floorY must be explicitly supplied by native navigation/content setup because the doorway reference derives it from navigation. The unturned source door and preferred approach are quarter-turned once, then converted metres [x,y,z] to Unreal cm [100z,100x,100y], then transformed with the complete native instance. Failed copies clear output. Kitchen, bathroom and legacy standing-point fallback are never physical door bindings. This does not translate the reference's candidate sorting, planRoomRoute or fallback-spawn clearance.

Loaded saved-room anchors are checked against those measured positions. Two sides of a connection must coincide after whole-level transforms rather than teleport between separated rooms. Source shell, supports, furniture and cameras remain unchanged. Native packages must already represent the exact saved design and decor; preparation does not apply another shell turn to saved furniture. Kitchen/bathroom extension remains an authored empty-front-strip requirement, not a whole-level scale operation. Missing native variants/openings are rejected rather than stretched or substituted.

Navigation copies use the already possessed native Character Movement agent and UE NavMesh projection/nonpartial path checks. They reject SliceCharacter, whose clamp/spawn remain exclusive to explicit offline inspection. They return only a candidate, not a spawn or move command. Camera copies keep canonical room-space references separate from apartment-space eye/target values; the existing controller/CameraManager remains the adoption owner. No neutral inspection camera/pawn is repurposed for a saved Home.

The visible-level daylight hook resolves real window, SkyLight, DirectionalLight, SkyAtmosphere, PostProcess and seating-view actors/components and queues sky capture once. It preserves authored intensity/direction/material/exposure settings. Missing bindings invalidate native content. A component binding or capture request does not verify large windows, daylight at the hallway entrance, a seating-to-exterior view or contemporary Lagos art.
