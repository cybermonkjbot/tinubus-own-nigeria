# Unreal native avatar ownership

October 10, 2026. Epic pages below identify UE 5.8. Existing evidence records installed UE 5.8.3; this sidecar performed no engine inspection or execution. These are integration requirements, not installed-content or acceptance claims. Reuse the prerequisites and furniture evidence without repeating their inventories. [R1][R2]

## Ownership decision

Reuse a trusted authored native/Blueprint actor class containing the complete skeletal/static component hierarchy, transforms and authored slot materials. Let native construction instantiate it; do not reconstruct GLB nodes in C++. Prefer `AActor` for apartment-owned presentation. Choose `ACharacter` when this instance must own capsule-based locomotion and possession, accounting for its capsule-relative mesh transform. A character's primary mesh is not the complete avatar inventory. This is a design recommendation, not a confirmed content binding. [E1][E2][R1]

## Preparation and validation

Spawn into the current room's `GetLoadedLevel()` using `FActorSpawnParameters::OverrideLevel`. `Owner` identifies another actor; `OverrideLevel` selects the actor's level/Outer. Check world, level and selection identity before and after spawning. Reuse furniture's transform-phase reconciliation, but account for the authored root's transform and scale. `AlwaysSpawn` and `RF_Transient` do not suppress gameplay. [E3][R2][R4]

Require hidden, noncolliding, inactive defaults before spawning. Disable actor and component ticks, physics, automatic input and both pawn auto-possession modes during preparation. Blueprint construction and `BeginPlay` must respect that preparation state. Hiding after `SpawnActor` returns is too late. Deferred spawning permits setup before Blueprint construction, but `FinishSpawning` resumes construction and initialization into `BeginPlay`; it is not an admission barrier. Recheck preparation after construction. [E1][E4][E5][R2]

Validate the completed instance, not only its class default object: Epic notes that CDO `GetComponents()` misses Blueprint-added components. Match declared component identities, hierarchy, actual mesh assets, source key/hash, unique slots, authored materials and parameter types. Names alone do not establish identity. The existing material adapter additionally requires registered components with the same actor owner/world. Child-actor meshes have another owner; reject that layout for this adapter or explicitly provide per-child ownership. Snapshot component arrays and revalidate around callbacks instead of retaining the live component set across mutations. [E4][E6][R3]

## Cleanup and deformation

On selection/access loss or replacement, suppress presentation, call `ClearPrivateMaterials()` while the old components remain valid, then tear down the actor and request room unload. Clear restores only slots still holding this adapter's MID, preserving previous overrides or null default lookup. Do not substitute furniture's blanket `EmptyOverrideMaterials()` for that restoration; it would discard authored component overrides. Keep cleanup idempotent and cover `EndPlay`/unregistration. Check `Destroy` failure. EndPlay need not mean immediate deallocation, so never assume a streamed-back instance has fresh private state. [R2][R3][E1]

Preserve every source skin binding, morph name and skeletal/static attachment through the accepted import mapping. Multiple glTF skins do not establish either one shared Unreal skeleton or one skeleton per skin. Verify each native mapping. Leader Pose requires matching bone structure; Copy Pose copies matching bones and needs correct tick ordering. Standard skeletal merging does not transfer morph targets. Neither is an automatic replacement for the authored hierarchy. [R1][E2]

Acceptance remains separate: real packages, complete occurrence coverage, rig/morph behavior, material graph wiring, rendered appearance and admission. Successful construction or material application proves none of those collectively. No asset paths or readiness claims are introduced here. [R1][R3]

## Parent source implementation

`ABaddieCompanionCharacterActor` now owns `CharacterMaterials`. It uses a trusted authored actor class with an identity root and the imported hierarchy in component templates. Named material definitions become instance-owned bindings after construction. The actor preserves authored component visibility while globally hidden. It rejects child-actor layouts, automatic input and replication. Default checks and suppression around initialization/BeginPlay are not a Blueprint-script audit; accepted content must have no gameplay/construction actions and must start with inactive components.

`NativeApartment` now loads the class and required material/mesh references through UE's existing streamable manager, retaining the handle until a prepared actor owns them. The private actor is spawned in exactly one Home level. It uses the source preferred Home pose and character scale, then reconciles the same native level-transform phase used by furniture. That pose is not verified spawn clearance. Cancellation or replacement clears materials before releasing the actor's mesh references and destroying it. Whole-actor disposal deliberately discards authored overrides too, after the material module's restoration; the discarded instance is never reused. Generation checks reject an actor returned after its owner was cleared. Unregister and EndPlay cancel loads and clear private content.

The initial Mac `bafdbfb9e` handoff was held because its guard covered `Prepare` but not material restoration from `OnUnregister`. `cribtest11-native-avatar-handoff-review-2026-10-10.md` records the finding. The correction checks `CharacterMaterials::IsChangingMaterials()` during clearing and guards actor suppression, preparation and transform reconciliation. All apartment-owned destruction requests now pass through `DestroyPrivateCharacter`. Recursive clearing or an active native mutation leaves the actor discarded and suppressed, deferring disposal through a weak `FTSTicker` delegate. This callback retains no snapshot and checks the guards again. Pending disposal is an accepted request, not confirmed destruction; deferred destruction failure produces a fixed diagnostic.

The ticker retains the same entry while blocked, then stops after safe cleanup. Installed `Runtime/Core/Public/Containers/Ticker.h` documents default delay zero and at most one call per ticker entry per core tick. `Runtime/Core/Private/Containers/Ticker.cpp:93-140` also drains newly added tickers during the same tick, so a retry must return true instead of enqueueing another zero-delay entry. Lines 163-166 execute the delegate only while it is bound. The parent inspected these files over read-only SSH on October 10. This is source evidence, not a runtime acceptance result.

The accessory continuation uses this lifetime for saved necklace and hip-chain visibility. It checks accepted per-mesh source masks and loaded identities before applying non-propagating native visibility setters. `unreal-accessory-visibility-reuse-2026-10-10.md` owns that contract and the remaining eyewear dependency.

The subsequent handoff review found that accessory callbacks could clear the material module while character preparation still succeeded. The material module now exposes the identity of its last successful application. Clear, unregistration, EndPlay and a new nonrecursive application invalidate that identity immediately. A successful application receives a new generation after all binding checks pass; generations never wrap or reuse zero. The character captures that identity before accessory setters, checks it after each setter and the full pass, and retains the same requirement during level-transform reconciliation. Registration alone cannot satisfy this check after unregister/re-register or replacement application. Character clearing also drops its captured generation. These guards establish source cancellation behavior, not rendered acceptance.

The actor has no activation, possession, camera, movement or animation implementation. Both the existing complete-inventory check and the closed admission/render-readiness conditions remain before any load or spawn. No native class, mesh, material graph or map was imported. Tests, compilation and engine launches were not run; this is source integration only.
