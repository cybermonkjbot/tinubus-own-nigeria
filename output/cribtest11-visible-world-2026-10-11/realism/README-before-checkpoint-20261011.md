# Native local Yaba quality slice

This is additive Unreal authoring, not production renderer integration or a generated Yaba district. The local X-axis runs along a proposed 120m quality slice. Canonical fictional city coordinates and runtime gates remain unchanged. Geography supplies a later district transform; it does not block local art.

`author_slice.py` runs inside the inspected Windows editor through the existing `python_bridge.py`. `prepare_native(expected_pid)` saves a fresh, non-partitioned map with five local walking/detail cameras, movable lights, manual exposure and seven explicitly untextured material-input assets. Its native receipt is immutable. The executed preparation source is preserved byte-matched under the realism evidence directory. These assets are setup, not photographic materials or finished street content.

`import_kit(expected_pid, manifest_path, expected_sha256, revision, preset)` imports a delivered, hash-bound detailed kit into a new content-addressed namespace. `import-contract.json` documents the native mapping. Source authors need not use this wrapper; the Unreal writer can adapt delivered `execution.json`, `material-bindings.json` and `placement.json` into a new owned manifest without changing incoming files. Before import, resolve their exact bounds, material slots, source axis conversion and UV evidence. Missing media fails before mutation. No input is fetched over the network.

Explicit `uvBasis` matters: raw `metres` UVs divide once by texture coverage; `physical-tiled` UVs such as the parent frontage's `SurfaceUV` already divide by coverage and use native tiling 1. Basecolour is sRGB. Roughness/metallic/AO are separate noncolour R maps. Normal maps use normal compression and noncolour sampling: DX is retained, GL green is flipped exactly once. Texture licence/source files and hashes are retained. Materials without maps remain labelled fallback and do not establish finish quality.

The guarded importer retains source normals, metre/tiled UVs and supplied mesh LODs. Native bounds and supplied vertex UV samples are checked. Actor scale stays 1; placement metres convert to centimetres once. A completed asset receipt supports additive daylight/evening map reuse without reimport or immutable source-map edits. Interrupted unreceipted imports stop for ownership review rather than overwrite.

`prepare_view(expected_pid, camera_id)` sets native camera/game-view state without piloting actors. After detailed geometry has been saved, `capture_slice.py --expected-pid PID --receipt PATH --camera ID --label NAME` verifies the saved map receipt, project/listener/PID, camera pose/FOV and at least eight advancing native frames before one CaptureViewport PNG. It is not executed on the empty setup. Camera positions are preparation values; retarget against detailed actor bounds before final image work. Capture/visual acceptance and gameplay acceptance remain separate.

No World duplication is used. World/Actor wrappers are scoped and never carried through level creation. No static lighting bake, navigation/HLOD build, compilation, tests or runtime admission is invoked. The preview uses the existing D3D11 Microsoft Basic Render Driver; no Nanite/Lumen or measured performance claim follows. The bounded slice is non-partitioned. Installed WorldPartition/DataLayer/HLOD/spline/water/PCG APIs are available, but default external-actor packages route outside the exclusive Content namespace, so streaming implementation is a separate ownership decision.
